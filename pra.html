Steps

  2. Split the data into X (three numeric features) and y (Result). Drop the Student column — it is an identifier, not a feature.
  3. Split into 75% training / 25% testing, stratified so both classes appear in the test set.

practical1_tree.py 
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.metrics import accuracy_score, confusion_matrix, classification_report

df = pd.read_csv("students.csv")
print(df.shape)
print(df.head())

X = df[["Attendance", "Assignment", "Exam"]]
y = df["Result"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)

model = DecisionTreeClassifier(max_depth=3, random_state=42)
model.fit(X_train, y_train)

y_pred = model.predict(X_test)

print("Accuracy:", round(accuracy_score(y_test, y_pred), 3))
print("\nConfusion matrix (rows = actual, cols = predicted):")
print(confusion_matrix(y_test, y_pred, labels=["Fail", "Pass"]))
print("\nClassification report:")
print(classification_report(y_test, y_pred))

print("\nLearned rules:")
print(export_text(model, feature_names=["Attendance", "Assignment", "Exam"]))

Interpretation

The tree learned a single, interpretable rule: if attendance is at or below 62.5%, predict Fail; otherwise predict Pass. In this small fictional dataset attendance is a perfect separator, so every test record is classified correctly.

Be honest about the limits

The test set has only 5 rows. 100% accuracy on 5 rows is not evidence that the model generalises. A real report should say: “On this small fictional sample the tree was perfectly accurate; a larger dataset with overlapping classes would be needed to estimate real performance.” Also note that 100% accuracy does not prove causation — high attendance may co-occur with other advantages.

Ethics note

The model is a screening aid, not a verdict. A student predicted as “Fail” should receive support (tutoring, a conversation), never punishment. Data are synthetic — no real student records appear in this file.

import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score, mean_absolute_error

df = pd.read_csv("study_hours.csv")
X = df[["Hours"]]
y = df["Score"]

model = LinearRegression()
model.fit(X, y)

print("Slope (m)     :", round(model.coef_[0], 3))
print("Intercept (c) :", round(model.intercept_, 3))

y_pred = model.predict(X)
print("R²            :", round(r2_score(y, y_pred), 4))
print("MAE           :", round(mean_absolute_error(y, y_pred), 2))

new = pd.DataFrame({"Hours": [6.5]})
print("Prediction for 6.5 hours:", round(model.predict(new)[0], 2))
Slope (m)     : 5.957
Intercept (c) : 39.126
R²            : 0.9965
MAE           : 0.62
Prediction for 6.5 hours: 77.85

Interpretation

The fitted line is Score = 39.13 + 5.96 × Hours. The slope means that, in this fictional dataset, each additional hour of study is associated with about 6 extra marks. The R² of 0.9965 means the line explains almost all the variation — but that is because this dataset was generated to be almost perfectly linear. The MAE of 0.62 says the average prediction is less than one mark away from the actual value.

For 6.5 hours the model estimates 77.85. This is a point estimate from a very clean synthetic sample — real exam scores scatter far more widely around any fitted line.

Correlation is not causation

A strong R² does not prove that studying causes higher marks. Prior knowledge, teaching quality, health and motivation may all affect both variables. It would also be unsafe to predict outside 1–8 hours; the model has never seen 20 hours and its extrapolation would be unreliable.

Ethics note

Regression estimates should never be used to set a fixed expectation for a named student. The dataset is fictional and contains no personal identifiers.

Steps

  1. Read the CSV and split each Items string into a Python set.
  2. Count how many transactions contain each item, and how many contain each candidate pair.
  3. Compute support, confidence and lift for the rules that interest you.
  4. Interpret lift: > 1 means the items co-occur more often than chance; = 1 means independent; < 1 means they repel.
  5. Choose one rule with lift > 1 and explain what action it justifies.
practical4_association.py 
import pandas as pd

df = pd.read_csv("transactions.csv")
baskets = [set(s.split(", ")) for s in df["Items"]]
n = len(baskets)

def metrics(a, b):
    A   = sum(a in t for t in baskets)
    B   = sum(b in t for t in baskets)
    AB  = sum(a in t and b in t for t in baskets)
    support    = AB / n
    confidence = AB / A if A else 0
    lift       = confidence / (B / n) if B else 0
    return A, B, AB, support, confidence, lift

pairs = [
    ("Bread",   "Milk"),
    ("Milk",    "Bread"),
    ("Diapers", "Beer"),
    ("Beer",    "Diapers"),
    ("Diapers", "Milk"),
    ("Bread",   "Diapers"),
]

print(f"{'Rule':<20}{'Sup(A)':>8}{'Sup(B)':>8}{'Sup(A,B)':>10}"
      f"{'Support':>10}{'Confidence':>12}{'Lift':>8}")
print("-" * 78)
for a, b in pairs:
    A, B, AB, sup, conf, lift = metrics(a, b)
    print(f"{a + ' -> ' + b:<20}{A:>8}{B:>8}{AB:>10}"
          f"{sup:>10.2f}{conf:>12.3f}{lift:>8.2f}")

Interpretation

  • Diapers → Beer has lift 1.33: customers who buy diapers are about one third more likely than a random customer to also buy beer. Confidence 0.667 means two-thirds of diaper baskets contained beer. This is the only clearly positive, actionable association in this small fictional basket set.
  • Bread → Milk and Milk → Bread both have lift 0.89 — below 1, meaning bread and milk appear together slightly less often than chance in this dataset. They are popular individually, but not a bundle.
  • Bread → Diapers has lift 0.95 — essentially independent.
Statistical caution

With only 10 transactions, a single basket change can swing support by 10 percentage points. Rules found on 10 baskets are hypotheses, not findings. A real analysis would require hundreds or thousands of receipts, a minimum-support threshold, and a significance check.

Ethics note

Basket analysis uses anonymised receipts only. It must never be linked back to a named customer, and rules must not be used to target vulnerable shoppers (for example, pushing alcohol to known buyers). Store-layout decisions are a legitimate use; personalised persuasion of individuals is not.

practical5_fraud.py 
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import (accuracy_score, confusion_matrix,
                             precision_score, recall_score, f1_score)

df = pd.read_csv("transactions_fraud.csv")
print("Class counts:")
print(df["Class"].value_counts())

X = df[["Amount", "Hour", "Distance_km", "Foreign"]]
y = df["Class"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)

model = DecisionTreeClassifier(max_depth=3, random_state=42)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)

print("\nConfusion matrix (rows = actual, cols = predicted):")
print(confusion_matrix(y_test, y_pred, labels=[0, 1]))

print("\nAccuracy :", round(accuracy_score(y_test, y_pred), 3))
print("Precision:", round(precision_score(y_test, y_pred, zero_division=0), 3))
print("Recall   :", round(recall_score(y_test, y_pred, zero_division=0), 3))
print("F1       :", round(f1_score(y_test, y_pred, zero_division=0), 3))

Interpretation

The model catches 1 of the 2 fraud cases in the test set (Recall = 0.50) and raises one false alarm (Precision = 0.50). Accuracy is 75% — but here is the trap: a lazy model that predicted “legitimate” for every transaction would score 26/32 = 81% accuracy while catching zero fraud. Accuracy is not the right metric for imbalanced data.

The correct question is: what does each mistake cost? A missed fraud (False Negative) may cost the bank thousands; a false alarm (False Positive) costs one SMS and a customer confirmation. Because missed fraud is more expensive, a real system would be tuned for higher recall, even at the cost of lower precision.

Small test set warning

With only 8 test rows, one prediction changes accuracy by 12.5%. The numbers above are illustrative; a real fraud study would use tens of thousands of transactions and report Precision–Recall curves at several thresholds.

Ethics note

A fraud flag should trigger human review and customer confirmation, never an automatic account block. Models must be tested for equal recall across age groups, regions and income levels — a biased model could freeze the accounts of one group disproportionately.

Interpretation

Scaling raised accuracy from 0.67 to 0.83. The reason is geometric. In the unscaled data, Tenure_months ranges up to 72 and Monthly_Charge up to 110, while Support_Calls only ranges from 0 to 8. Ethics note

import pandas as pd
import numpy as np

df = pd.read_csv("sensor_readings.csv")
x = df["Temperature_C"]

# --- IQR method ---
q1, q3 = x.quantile(0.25), x.quantile(0.75)
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr

print(f"Q1 = {q1:.2f}, Q3 = {q3:.2f}, IQR = {iqr:.2f}")
print(f"Bounds: [{lower:.2f}, {upper:.2f}]")
iqr_flags = df[(x < lower) | (x > upper)]
print("\nFlagged by IQR:")
print(iqr_flags[["ReadingID", "Temperature_C"]].to_string(index=False))

# --- Z-score method ---
mean, sd = x.mean(), x.std(ddof=0)
z = (x - mean) / sd
print(f"\nMean = {mean:.2f}, Std = {sd:.2f}")
print("\nZ-scores of the suspects:")
for rid, val, zval in zip(df["ReadingID"], x, z):
    if abs(zval) > 1.5:
        print(f"  ID {rid:>2}  value={val:>7.1f}  z={zval: .2f}")

z_flags = df[np.abs(z) > 2]
print("\nFlagged by Z-score (|z| > 2):")
print(z_flags[["ReadingID", "Temperature_C"]].to_string(index=False))

Interpretation

The IQR method correctly flags all three anomalies: 48.5 °C, −5.2 °C and 92.0 °C. The Z-score method with the usual |z| > 2 threshold flags only two — it misses 48.5 °C.

This is the masking effect. Because 92.0 °C is so extreme, it inflates the standard deviation to 14.30. Every other Z-score is divided by that inflated number, so a genuinely anomalous 48.5 °C gets a Z-score of only 1.68. One extreme point has hidden another.

Which method should you use?

When outliers may be present, prefer IQR or median absolute deviation (MAD). Both are robust — they depend on the middle of the data, not on the extremes. The Z-score method assumes the data are roughly normal without serious outliers, which is exactly the situation you are trying to detect. If you do use Z-scores, compute the mean and standard deviation from the cleaned data (after removing the obvious extremes) and then apply the rule.

Ethics note

Flagging is not deleting. An anomalous 48.5 °C could be a real sensor fault, or a genuine event (a fire). A technician should investigate before any record is removed.

KNN (scaled)0.80 Scaling puts all three features on the same footing, so CGPA and Internships now affect the neighbours. Still below the tree because KNN struggles when classes are separated by sharp thresholds rather than by distance.
The lesson

There is no universally best algorithm. A Decision Tree is better when the underlying rule is “if X > threshold then …”. KNN is better when similar cases cluster together in feature space. And scaling is not optional for KNN — it changed the result from 0.60 to 0.80.

Ethics note

A placement model must not be used to quietly exclude students. If used at all, it should trigger support (mock interviews, aptitude coaching) for students flagged as “at risk”, and every student should be able to see and contest the data held about them.

Steps

  1. Read the CSV and split each Courses string into a set.
  2. Count how many students take each course and each candidate pair.
  3. Compute support, confidence and lift for a set of candidate rules.
  4. Apply a minimum-support filter of 0.25 and report only the rules that pass.
  5. Identify one rule the department could act on, and one rule that looks tempting but fails the support threshold.
practical12_enrollment.py 
import pandas as pd

df = pd.read_csv("enrollment.csv")
baskets = [set(s.split(", ")) for s in df["Courses"]]
n = len(baskets)

def metrics(a, b):
    A  = sum(a in s for s in baskets)
    B  = sum(b in s for s in baskets)
    AB = sum(a in s and b in s for s in baskets)
    sup    = AB / n
    conf   = AB / A if A else 0
    lift   = conf / (B / n) if B else 0
    return A, B, AB, sup, conf, lift

candidates = [
    ("DM", "DB"),
    ("DB", "DM"),
    ("DM", "ML"),
    ("ML", "DM"),
    ("ML", "PY"),
    ("DM", "PY"),
    ("PY", "ML"),
    ("ML", "AI"),
]

MIN_SUPPORT = 0.25
print(f"Minimum support filter = {MIN_SUPPORT}")
print(f"{'Rule':<12}{'Sup':>6}{'Conf':>7}{'Lift':>7}   Pass?")
print("-" * 46)
for a, b in candidates:
    A, B, AB, sup, conf, lift = metrics(a, b)
    passed = "YES" if sup >= MIN_SUPPORT else "no"
    print(f"{a + '->' + b:<12}{sup:>6.2f}{conf:>7.2f}{lift:>7.2f}   {passed}")

Interpretation

  • DM → DB (support 0.50, confidence 0.75, lift 1.13) is the strongest supported rule. Half of all students take both, and three-quarters of DM students also take DB. Action: schedule DM and DB in adjacent time slots and consider advertising DB as a natural companion to DM.
  • DM → ML (support 0.42, confidence 0.62, lift 1.07) is a weaker but still positive association. Action: note it in advising material.
  • ML → AI has the highest lift (1.71) but only 8% support — only one student takes both. This is a perfect illustration of the trap: lift alone is not enough. A rule based on one student is not a pattern; it is an anecdote. It fails the minimum-support filter and should not drive any decision.
The one-sentence takeaway

Support tells you whether a rule is common enough to matter; lift tells you whether it is stronger than chance. A useful rule needs both.

Ethics note

Enrolment patterns must not be used to restrict a student's course choice. Their only legitimate use is to improve timetabling and advising. The data are synthetic and contain no student identifiers.
