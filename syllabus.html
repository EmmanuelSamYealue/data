2. Course Description

TECH 307 – Data Mining Techniques introduces students to the systematic process of discovering useful patterns, relationships and knowledge from large volumes of raw data. The course follows the complete Knowledge Discovery in Databases (KDD) pipeline: understanding the problem, selecting and collecting data, cleaning and quality-assuring it, transforming and reducing it, applying a mining technique, evaluating the results, and communicating findings responsibly.

Students learn the distinction between data, information, knowledge and patterns; the major types of data that can be mined (relational databases, data warehouses, transactional data, streams, text and multimedia); and the principal data mining functionalities: concept description, association rule mining, classification, regression, clustering and anomaly detection.

The course is strongly practical. Using Python with pandas, and matplotlib, students write working code to load, inspect, clean, transform, visualise and mine real and synthetic datasets. A capstone mini-project requires students to apply the whole KDD process end-to-end to a dataset of their own choosing and to defend their results in a short presentation.

Throughout the course, students are expected to reason critically about ethics, privacy, bias and fairness. Data mining results can affect real people; students must understand that a model is an advisory tool, not a final judge, and that high-stakes decisions require human oversight, transparency and an appeal mechanism.

Graduate Attributes Developed
  • Critical thinking — evaluating data quality and model results rather than accepting them at face value.
  • Digital literacy — competent, safe and ethical use of data and analytical software.
  • Communication — presenting analytical findings to non-technical audiences.
  • Professional ethics — recognising bias, protecting privacy, documenting decisions.

4. Pre-requisites & Co-requisites

Based on the program's course guide, TECH 307 builds upon foundational concepts established in Level 100 and Level 200 courses. Students must have completed the following:

Pre-requisites

  • MATH 207: Probability and Statistics — Essential for understanding data distributions, mean, median, variance, standard deviation, and hypothesis testing.
  • TECH 209: Python Programming (or TECH 104: Introduction to Programming using C++) — Required for the practical coding components of this course.
  • TECH 102: Database Management System I — Basic understanding of tables, rows, columns, and relational data structures.

Co-requisites / Helpful Background

  • TECH 205: Database Management System II — SQL querying and data manipulation are highly beneficial for data extraction.
  • TECH 203: System Administration and Virtualization — Helpful for setting up local development environments and managing datasets.
  • No prior experience with machine learning or specific data mining tools (like WEKA or scikit-learn) is assumed — Module 4 covers the software setup from scratch.

5. Course Content & Weekly Syllabus

The course is organised into 26 learning modules delivered over 15 teaching weeks. Weeks 1–9 build the conceptual and data-preparation foundation; Weeks 10–14 cover the core mining algorithms; Week 15 consolidates applications, ethics and project work.

WeekTopicKey ConceptsModule(s)
1 Introduction to Data Mining & the KDD Process Definition of data mining; data → information → knowledge → pattern; the six KDD stages; why cleaning dominates real projects. 1
2 Types of Data Mined Relational databases; data warehouses and the data cube (OLAP); transactional / basket data; sequence, stream, text and web data. 2
3 Data Mining Functionalities Characterisation vs discrimination; frequent patterns, association and correlation; classification vs regression; cluster analysis; outlier analysis. 3
4 Software Setup & Environment - Installing Python and VS Code; virtual environments; pandas, numpy, matplotlib, seaborn, scikit-learn; troubleshooting imports and file paths. 4
5 Data Collection & Inspection CSV vs DataFrame; records, attributes, features, labels; numerical / categorical / text / date / boolean types; structured vs unstructured; head(), shape, info(), describe(). 5
6 Data Cleaning & Quality Missing values; duplicates; inconsistent categories; invalid values; outliers; the six data quality dimensions; documenting a cleaning log. 6, 22
7 Data Transformation & Reduction Min–max normalisation; z-score standardisation; label vs one-hot encoding and the dummy-variable trap; aggregation; sampling; binning; attribute selection. 7
8 Exploratory Data Analysis Mean, median, mode; range, standard deviation, IQR; skewness and the mean–median relationship; box plots and the five-number summary. 8
9 Data Visualisation Bar, histogram, line and scatter plots; choosing the right chart; correlation vs causation; honesty in charts (axes, scale, labelling). 9
10 Introduction to Classification Supervised learning; features (X) vs label (y); train/test split; why testing on training data is invalid; overfitting. 10
11 Decision Trees & K-Nearest Neighbours - Root, decision nodes, branches, leaves; interpretable rules; KNN distance and neighbour voting; why KNN requires scaling. 11
12 Model Evaluation Confusion matrix (TP/TN/FP/FN); accuracy, precision, recall, F1; why accuracy fails on imbalanced data; choosing a threshold from error costs. 12
13 Clustering with K-Means Unsupervised learning; intra-class vs inter-class similarity; the K-Means loop; choosing K (elbow, silhouette); interpreting clusters without over-labelling. 13
14 Association Rule Mining Market basket analysis; support, confidence, lift; interpreting lift > 1, = 1, < 1; minimum-support pruning; actionable vs spurious rules. 14

6. Teaching & Learning Strategies

  • Interactive lectures — concepts introduced with worked examples and live demonstration of code.
  • Laboratory practicals — guided, hands-on coding sessions on real and synthetic datasets.
  • Problem-based learning — small groups analyse a dataset and defend their chosen technique and threshold.
  • Peer review — students review each other's cleaning logs and charts before final submission.
  • Mini-project — a scaffolded, semester-long assessment that mirrors professional practice.
  • Blended resources — an interactive HTML lecture guide (26 modules), screencasts, and a curated reading list.

9. Prescribed Textbook

Primary Text

Han, J., Kamber, M., & Pei, J. (2022). Data Mining: Concepts and Techniques (4th ed.). Morgan Kaufmann / Elsevier. ISBN 978-0-12-811760-6.

The authoritative reference for the conceptual content of Modules 1–3 and 10–16. Chapters 1–3 cover the KDD process, data types and functionalities; Chapters 6–8 cover association, classification and cluster analysis.

Primary Practical Text

Witten, I. H., Frank, E., Hall, M. A., & Pal, C. J. (2016). Data Mining: Practical Machine Learning Tools and Techniques (4th ed.). Morgan Kaufmann. ISBN 978-0-12-804291-5.

Pairs directly with WEKA and gives strong coverage of evaluation methodology, which underpins the mini-project marking criteria.

11. Academic Integrity, Ethics & Data Policy

Rules that apply to all submitted work
  • Never submit identifiable personal data. Names, student IDs, phone numbers, addresses, email addresses and health records must be removed or replaced with pseudonyms before a dataset is used in any assignment or project.
  • Label synthetic data as fictional. If you generate data yourself, state this clearly in the report so that no reader mistakes it for real records.
  • Cite your data source — URL, access date, licence, and any preprocessing performed by the provider.
  • Credit all code you did not write. Copying code from a tutorial, a peer or an AI assistant without attribution is plagiarism. You must be able to explain every line you submit.
  • Report results honestly. Do not delete inconvenient results, cherry-pick a favourable train/test split, or report only accuracy when the classes are imbalanced.
  • Document cleaning decisions. Every value filled, row dropped or category standardised must be recorded with a reason.

Ethical principles expected in every project

  • Privacy & data minimisation — collect and use only what the question requires.
  • Consent & purpose limitation — participants should know how their data will be used; do not reuse data for unrelated purposes.
  • Fairness — check whether under-represented groups are missing from the dataset and whether error rates differ between groups.
  • Human oversight — no high-stakes decision (grades, loans, hiring, medical triage) should rest on a model alone. Provide review and appeal.
  • Transparency — prefer explainable models in high-stakes settings, and document limitations in the report.
